PMM Agent — System Architecture

Operation Blackbriar · deterministic orchestration, agentic execution, human-gated publication

Deterministic Orchestration, Agentic Execution

  • • Orchestration is code: pipeline sequencing, sign-off gates, retries, and validation are auditable code paths — never an LLM plan
  • • Agents are autonomous inside their step: the answer loop picks its evidence tools, the router classifies intent, extraction decides what the sources support
  • • Two dynamic dispatch points: the ask-router (question vs. artifact) and the tool-using answer loop — both degrade safely, never block

Governance — the Trust Architecture

  • • Intelligence before activation: no artifact generates without a PMM-approved (final) messaging doc behind it
  • • Voice guard and citation filters are deterministic code — model judgment is never the only defense
  • • Every publish requires a named human: questionnaire sign-off, doc approval, artifact finalize — all attributed in the activity log

The 21-Agent Registry

  • • 7 task agents power the pipelines; 14 PMM sub-agents mirror the operating playbook (intelligence · activation · governance)
  • • Every agent is configurable from the Agents console: instructions, model, enabled, full override — with test-run preview and one-click revert
  • • Locked contract suffixes are appended in code, so no override can remove the JSON output contract a pipeline parses
