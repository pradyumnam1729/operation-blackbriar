# 15 — System of Record Definitions

## The Core Question

The single most important thing to get right with an integrated deployment is answering clearly: "For this piece of data, which system is the master?" When both systems claim ownership over the same field, you get conflict, inconsistency, and user confusion. When ownership is explicit, both systems work together without friction.

Aurigo Maintain is a **System of Intelligence.** It computes insight from operational data. It does not compete with the EAM for ownership of operational records. It owns the intelligence layer that the EAM cannot provide.

## How Data Flows

### Read Path: EAM → Maintain

```
EAM system (Maximo, SAP, etc.)
    ↓ delta sync every 15 min via IEamAdapter
Integration Gateway
    ↓ canonical mapping + conflict resolution
Maintain database (PostgreSQL)
    ↓ condition engine, RUL calculator, ARV engine, risk scorer
Intelligence layer (condition scores, RUL, ARV, risk, capital needs)
    ↓ exposed via Maintain REST API
Maintain UI (dashboards, capital plan, inspection workflows)
```

The EAM is the source. Maintain enriches and presents the intelligence.

### Write Path: Maintain → EAM (Hybrid Mode Only)

```
Maintain capital planning engine identifies maintenance need
    ↓ capital need approved in Maintain
Work order recommendation generated
    ↓ IEamAdapter.CreateWorkOrderAsync()
EAM system receives new work order
    ↓ maintenance team executes work order in EAM
Work order completion syncs back to Maintain via read path
    ↓ condition engine recalculates condition based on completed maintenance
Updated condition and RUL scores reflected in capital plan
```

The write path is optional (Hybrid Mode only) and narrow. Maintain creates work orders in the EAM but does not modify asset records, change PM schedules, or touch any other EAM data.

## Communicating System of Record to Customers

Customers frequently ask: "If I change something in Maximo, will it break Maintain?" The answer depends on what they change.

**Changes that sync to Maintain automatically (EAM-owned fields):**
- Renaming an asset in Maximo → asset name updates in Maintain on the next delta sync
- Adding a new asset in Maximo → new asset appears in Maintain within 15 minutes
- Decommissioning an asset in Maximo → asset status updates in Maintain (with conflict check)

**Changes that do NOT affect Maintain (Maintain-owned fields):**
- Maintain's condition score for an asset → not stored in Maximo, not affected by Maximo changes
- Maintain's capital need for an asset → not stored in Maximo
- Maintain's RUL projection → recalculated by Maintain engine, not from Maximo

**Changes that may cause a conflict review:**
- Changing an asset's location by more than 1 km in Maximo → triggers human review in Maintain
- Decommissioning an asset in Maximo that has an active capital need → triggers human review

Provide this table to the customer's system owner and Maximo/EAM administrator during onboarding. It prevents confusion and reduces support tickets.

## Data Governance Responsibility

| Role | Responsibility |
|---|---|
| Maintenance Department | EAM data quality — correct asset records, accurate work order completion data |
| GIS Team | Spatial accuracy — correct geometry in ArcGIS Feature Services |
| Asset Management Team | Maintain data quality — inspection frequency, condition standards, deterioration model tuning |
| IT / EAM Administrator | Integration health — sync monitoring, adapter configuration, credential management |
| Aurigo Implementation Team | Onboarding — field mapping, asset class configuration, initial data quality review |
| Aurigo Support | Ongoing — sync issue resolution, conflict review escalations, model updates |

## Native Mode: Maintain Becomes System of Record

In Native Mode, the EAM is retired or in archive mode. Maintain becomes the system of record for all data categories, including work orders, PM schedules, and the asset registry. The data flow diagram above inverts: there is no EAM to read from. All data lives in Maintain.

In Native Mode, the `adapterName` field on all records is set to `native`, and no sync jobs run. The integration layer is dormant but not removed — if the agency adds a new EAM system in the future (unusual but possible), the integration layer can be reactivated.
