# Chapter 3 — GA

**Volume 8 · PMM Agent Playbook · 2026-08-06**

---

## What GA Is For

Beta proved the operating model with Aurigo as a single, closely-watched tenant. GA makes the PMM Agent a product: a system a customer we do not sit next to can adopt, connect to their own stack, and use to demonstrate the value props from their own numbers. The four GA workstreams — live connectors, multi-tenancy, analytics, enterprise auth — are exactly the gaps beta's exit criteria left open by design.

## GA Scope

### 1. Live Connectors

The import pipelines of beta become scheduled, credentialed connectors per `pmm-playbook/vol-6-integrations/`:

- **Call platforms** (Gong, Chorus, Fathom, Granola): API pull on the weekly voice-of-market schedule; new transcripts land in intake without a human exporting anything.
- **CRM** (Salesforce first): scheduled opportunity sync, with closed-won/closed-lost events triggering the win-loss agent out of cycle.
- **Competitive monitors:** watched URLs (pricing pages, release-note feeds, G2 profiles) firing the event triggers of `pmm-playbook/vol-6-integrations/04-competitive-sources.md` automatically.
- **Product truth:** the repo/docs watch generalized so a tenant can designate their own feature-truth source, with `engineering-playbook/vol-2-product-knowledge/` remaining the reference implementation of the pattern.

The invariant holds from `pmm-playbook/vol-6-integrations/01-integration-overview.md`: connectors change transport, not the contract. Raw signal still normalizes into war-room markdown; agents still read only the war room; every asset still traces to dated source files. Connector health (last successful sync, per source) joins the governance dashboard's freshness board, because the failure mode of live connectors is silent staleness that no one is manually refreshing anymore.

### 2. Multi-Tenant

One deployment, many customers, with tenant isolation as a hard boundary:

- **Isolation model.** Each tenant's war room, agent configuration, guardrail lists, and connector credentials are fully partitioned. A tenant's raw customer language and win-loss data are competitively sensitive by definition; no cross-tenant retrieval, ever, including by agents. The engineering standards for tenancy come from the base playbook (`engineering-playbook/`, architecture volumes) and `pmm-playbook/vol-3-architecture/`.
- **Onboarding as product.** The seed-war-room flow (`pmm-playbook/vol-10-prompts/01-seed-war-room.md`) and the foundational-doc builder become the guided first-run experience: a new tenant's PMM builds their first foundational doc against the standardized framework, and the system is honest about which capabilities stay locked until sources are connected (the §2.2 prerequisite, surfaced as UX).
- **Framework constant, content per-tenant.** The canonical frameworks (Master Instructions §13 — Dunford positioning, the 7-step arc, the §7.4 value-prop schema) and the template library (`pmm-playbook/vol-9-templates/`) ship as the product's standard method. Brand DNA, terminology rules, and forbidden-word lists are tenant-configured — Aurigo's voice standards are the reference configuration, not a hard-coded default.

### 3. Analytics

Beta made the production metrics real; GA makes them a customer-facing analytics surface, because at GA the value props become claims a customer verifies from their own dashboard:

- **Asset usage rate** — % of active deals where system-generated collateral is used (from CRM connector data), the headline production metric per `pmm-playbook/vol-7-ai-engineering/04-evals.md`.
- **Messaging consistency score** — the automated consistency and swap-test evals across the tenant's asset library, trended: contradiction count, drift flags, swap-failure rate. This is the 100%-consistency value prop, measured continuously instead of asserted.
- **Time-to-asset** — request to approved final, by asset class: the 90%-faster claim with the tenant's own baseline.
- **Coverage** — products, personas, and segments with current foundational docs per PMM: the 3–5× multiplier, counted.
- **Program health and spend** — always-on run history and model cost per program, from the beta dashboard, hardened.

All metrics report on absolute periods and respect the small-number honesty rule of `pmm-playbook/vol-6-integrations/03-crm.md`.

### 4. Enterprise Auth

The persona system of Master Instructions §9 becomes an access-control model:

- **SSO** (SAML/OIDC) against the customer's identity provider; SCIM provisioning so role changes flow from the IdP.
- **Role model mapped to §9.2 personas:** PMM admin (full control: approvals, guardrail configuration, brand-DNA edits), contributor PMMs, and consuming roles (Sales, Proposals, Marketing, Leadership, Customer Success, SDR) who query and receive finals but never see drafts or edit the war room.
- **The approval permission is the crown jewel:** flipping `stage: draft` to `stage: final` is restricted to the PMM admin role, enforced in the authorization layer — the §8.4 gate as access control, not convention.
- **Audit log** — queries, generations, approvals, exports, and connector events, per tenant, exportable. Aurigo's public-sector customers will ask; the answer is yes.

## GA Exit Criteria

1. A tenant other than Aurigo onboards, connects at least CRM and one call platform, and reaches an approved foundational doc plus first generated assets without hands-on help from the build team.
2. Connectors run four weeks unattended per tenant, with failures surfacing on the dashboard rather than as silent staleness.
3. The analytics surface reports all four value-prop metrics from live tenant data.
4. Tenant isolation passes adversarial review per the security standards in the engineering playbook's security volume.
